# Решение Проблем

- **Сначала запускайте client, потом включайте WireGuard / Xray.**
- **Трафик не идет (нет интернета):** Проверьте серверный флаг `-connect`. В нем должен быть указан точный локальный порт, на котором слушает ваш VPN (например, `51820` для WG или `443` для VLESS). Если порт не совпадает, прокси будет стучаться в пустоту.
- **WireGuard забирает весь трафик:** пайп с `-debug 2>&1` и скриптом маршрутов обязателен (`scripts/routes.sh` / `scripts/routes.ps1` / `scripts/routes-macos.sh`). Маршруты не добавляются -> убедитесь, что в команде есть пайп перед скриптом.
- **DPI блокирует UDP:** Если используете `-transport udp` и ничего не работает, попробуйте убрать флаг (использовать TCP по умолчанию).
- **Обход шейпинга (кастомный TURN):** Если вы знаете "чистый" IP-адрес TURN-сервера VK, где нет агрессивного шейпинга, вы можете передать его вручную: `-turn <ip_address> -port <port>`. Это перезапишет данные, полученные из ссылки.
- **Проблемы с DNS на мобильном интернете:** Резолв ломается. Передайте DNS вашего провайдера явно: `-dns-servers <ip_dns>`.
- **Проблемы с MTU:** Если соединение обрывается или не грузятся тяжелые сайты, попробуйте снизить MTU в вашем VPN-клиенте (WireGuard/Amnezia) до `1280` или даже до `1120`. Из-за накладных расходов DTLS + TURN пакеты стандартного размера (1420) часто фрагментируются и отбрасываются.
- **Соединение нестабильное:** попробуйте уменьшить потоки `-n` (например, `-n 6`). Слишком большое число потоков может привести к бану.
- **VK часто требует captcha:** запустите с `-manual-captcha`, решите капчу в браузере, затем возвращайтесь к обычному запуску.
- **Клиент висит на получении TURN-данных:** ссылка VK Calls умерла / звонок завершён для всех.
- **Docker bridge mode:** `CONNECT_ADDR=127.0.0.1:...` указывает внутрь контейнера. Используйте `--network host` или IP хоста.
- **`-obf-profile != none`:** профиль и ключ должны совпадать на клиенте и сервере.

## Настольный клиент: профили, диагностика и восстановление сети

Следующее относится к текущей ветке `main`, не к опубликованной v3.0.6.
Советы про отдельный WireGuard-клиент и скрипты выше относятся к CLI/режиму
реле; встроенный VPN сам настраивает адаптер и маршруты.

### Профили

- Экспорт: «Серверы» → ПКМ по профилю → «Экспортировать профиль…».
  Файл `freeturn-profiles`, версия 1, содержит ключи WireGuard/маскировки и ссылки
  VK, необходимые для подключения. Не публикуйте его. SSH-данные исключены.
  После подтверждения появляется системный диалог выбора папки и имени файла;
  предлагаемое имя имеет вид `FreeTurn-profile-название.json`, например `FreeTurn-profile-Германия.json`.
  Его можно изменить; запрещённые символы автоматически заменяются, а для
  профиля без имени используется `FreeTurn-profile.json`.
  При отмене ничего не записывается. На Windows и Linux подтверждение использует
  системные «Да/Нет»: Wails не поддерживает произвольные подписи этих кнопок.
- Импорт: кнопка с иконкой и пунктирной рамкой справа от «Добавить сервер».
  Импортируются только корректные профили; файл проверяется целиком до записи.
  Создаются новые ID: существующие профили и активное соединение не заменяются.
  Ограничение — 8 МиБ и 100 профилей за один импорт. Импорт не запускает VPN/SSH.
- `servers.json.bak` рядом с `servers.json` хранит предыдущую исправную редакцию.
  Обе записи выполняются через приватные временные файлы. Ошибка записи не
  оставляет несохранённые изменения в памяти backend.
- При повреждении JSON оригинальные байты сохраняются в приватный файл
  `servers-damaged-*.json`. Если копия исправна, она восстанавливается
  автоматически. Если нет — приложение открывается с предупреждением и пустым
  списком, не затирая оригинал до явного сохранения/импорта.
- Для ручного восстановления: отключите соединение → «Настройки» →
  «Диагностика и восстановление» → «Восстановить профили». Будет подтверждение
  замены списка. Настройки автоподключения не переписываются: проверьте выбранный
  профиль, если его нет в восстановленной редакции.

### Отчёт диагностики

«Настройки» → «Сохранить диагностику» → выбрать JSON-файл. Отчёт содержит версии,
ОС/архитектуру, наличие VPN-helper, количество поднятых сетевых интерфейсов,
сводку режимов DNS/маршрутизации, счётчики трафика и до 100 последних изменений
состояния. Используется список разрешённых полей, не попытка скрыть секреты
регулярными выражениями в произвольных логах.

В отчёт не входят имена/адреса профилей, IP интерфейсов, URL captcha, пароли,
ключи, локальные пути и исходные сообщения ошибок/логи. Отчёт не выполняет
внешние запросы и не является проверкой DNS-утечек или доступности живого VPN.

### Проверка восстановления сети

Автотесты проверяют синтетические переходы потери/возврата потоков, сохранение
установленной сессии после исходного таймаута подключения, captcha во время
восстановления, отмену wake-проверки, живой/молчащий канал после пробуждения и
обнаружение завершившегося helper. Они не переключают Wi-Fi хоста и не решают
настоящую captcha.

Перед релизом на каждой ОС нужна ручная проверка с тестовым профилем:

| Сценарий | Ожидаемое поведение |
| --- | --- |
| Сон → пробуждение | Живой канал не перезапускается; молчащий переподключается после окна проверки |
| Wi-Fi → другая сеть | Потеря потоков отображается; после восстановления сети трафик снова проходит либо показана явная ошибка |
| Отключение интернета на 1–2 минуты | Ранее установленная сессия не обрывается по таймауту первого подключения |
| Captcha после возврата сети | Окно появляется автоматически, работающие потоки сохраняются |
| Аварийное завершение helper | Сессия не остаётся ложно подключённой; после очистки возможен повторный запуск |
| Отмена во время восстановления | Нет позднего самоподключения, повторного окна captcha или оставленных маршрутов/DNS |

Сравните маршруты и DNS до подключения и после отключения/ошибки. Не завершайте
системные сетевые службы и не используйте рабочие ключи для публичного отчёта.
