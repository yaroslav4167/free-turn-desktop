# FreeTurn Desktop v3.0.9

## Локальная сеть в обход VPN

- В разделе профиля **«Списки маршрутизации VPN»** добавлен переключатель **«Локальная сеть в обход VPN»**. Он включён по умолчанию — как для новых, так и для ранее сохранённых профилей.
- Локальные и частные IPv4/IPv6-адреса исключаются из маршрутов FreeTurn и используют обычные маршруты ОС. Это позволяет обращаться к роутерам, NAS, принтерам, локальным сервисам и частным корпоративным сетям через существующее подключение.
- Поддерживаются RFC1918, CGNAT, localhost, link-local, IPv6 ULA/site-local, multicast и broadcast, а также непосредственно подключённые подсети активных физических интерфейсов. Собственный TUN FreeTurn и point-to-point туннели не принимаются за физическую LAN.
- Автоматические исключения имеют приоритет над белыми списками и не занимают пользовательские 16 списков/256 записей. Ограничение итогового количества маршрутов сохранено.
- Настройка сохраняется для каждого профиля и переносится в JSON-экспорте. Явно выключенное состояние не сбрасывается при сохранении, перезапуске или импорте.
- Для применения сохраните профиль и переподключитесь. Во время подключения изменение заблокировано. Режим реле, отдельный CLI и внешний WireGuard-клиент настройка не меняет.

## Важные особенности

- **Если частная сеть должна быть доступна через сам FreeTurn VPN, выключите обход.** Это относится к удалённым внутренним сервисам и SSH на частных адресах. Если после исключений не остаётся VPN-маршрутов, приложение выдаёт понятную ошибку, а не имитирует успешное подключение.
- **VPN-DNS остаётся служебным исключением:** адрес DNS-сервера профиля сохраняет маршрут через VPN внутри исходных `AllowedIPs`, даже если он частный. Криптографические `AllowedIPs` не расширяются.
- Обход адресов не является автоматическим split-DNS. Для внутренних доменных имён нужен доступный корпоративный DNS и корректные настройки ОС.
- Публичные корпоративные подсети за шлюзом, не назначенные физическому интерфейсу, можно добавить в чёрный список. После смены публичной локальной подсети переподключитесь для обновления снимка интерфейсов.
- Это маршрутизация, не блокировщик и не защита от утечек. Одновременный доступ к двум устройствам с одним и тем же IP в разных сетях требует устранения конфликта адресов или другой маршрутизации.

## Совместимость интерфейса VPN

- При включённом обходе адреса самого TUN назначаются в ОС как `/32` и `/128`. Так его автоматически созданная connected-подсеть не перехватывает LAN вопреки исключениям. Сами IP, ключи и сохранённый WireGuard-конфиг не меняются.
- При выключенной опции сохраняются исходные маски и обычные правила маршрутизации профиля.
- В поставляемом helper Linux исправлена потеря узловых битов адреса при разборе широких масок интерфейса. Системный Linux helper не заменяется автоматически при обновлении GUI; для его обновления используйте установщик из нового архива.
- Сохранены нативные Linux helper, Windows Wintun и macOS utun/launchd helper, а также существующие правила маршрутизации, профили и ключи.

## Документация и проверки

Добавлены инструкция по локальным сетям, пояснения конфликтов DNS/частных адресов и демонстрационный снимок переключателя. Документация включена в Linux-архив.

Тестируются IPv4/IPv6 и границы диапазонов, приоритет над белыми списками, сохранение VPN-DNS, подключённые публичные подсети, отсутствие расширения `AllowedIPs`, пустые планы, отмена, лимиты, маски TUN и перенос настройки между сохранением/экспортом/импортом.

Публикация требует успешных четырёх нативных сборок, тестов и проверки SHA-256 архивов: Windows x64, Linux x64, macOS Apple Silicon и Intel. Автотесты и синтетический предпросмотр не подтверждают работу конкретной корпоративной сети, её DNS, живой captcha VK или отсутствие утечек на каждой ОС. macOS-сборки подписаны ad-hoc, без Developer ID notarization.
